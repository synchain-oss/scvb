# KNOWN_ISSUES —— SCVB v1 已知限制

本文件记录 v1 已裁定接受、且不构成发版阻断的已知限制。每个条目写明「现象 / 原因 / 影响 / 缓解 / 彻底修复方向」。新增条目遵循同一格式。

## KI-1:run 切换时旧 run 尾部 ≤40ms 漏拉(04 异议 1)

- **现象**:增量拉取(04 §3.3)的读方以 base_hop 前后双读 + write_hop 做 seqlock 校验。若 run 切换(跳变 / 停止 / 开关)发生在两次 25Hz 轮询之间,旧 run 尚未拉取的尾部 hop 会被跳过,不并入 FrameStore。
- **原因**:FeatHeader 只有 base_hop / write_hop 两个寻址字段(ipc-contract §3 冻结布局),没有 run_id。切换后 base_hop 已指向新 run 起点,读方见 base != lastBase 即重置 lastPulled = base,旧 run 未拉积压整段跳过——旧 write_hop 已被新 run 覆盖,无法界定,永不补拉。
- **影响(已裁定接受)**:常态 ≤40ms(≈4 hop),且 run 切换通常落在换气/静音概率区,分析层 guard(04 §4.3 R⁺)与 padding 吸收;最坏情形 = 切换发生在 [M] 长停顿期间(加载工程/模态框/插件扫描,J10 场景),上限 = 停顿时长。**无假覆盖**:coverage 如实显洞 → UI 显示未采集 → 补播即复原。
- **缓解**:无(数据不可追回);后果可自愈(补播)。受限追赶(kMaxBurstHops=256)只保证 **run 不变**时的积压分拍补完,不覆盖 run 切换。
- **彻底修复方向**:FeatHeader 增 run_id(需 abi+1 且段名升 v2,04 文末异议 1 / J35)。v1 不做。

## KI-2:Cubase 15 下编辑器(WebView2)开不出来时的排查指引

- **现象**:暂无已确认故障。本条最初是**基线缺口登记**(当时 Cubase 15 上没有实测数据),不是已知 bug;现在保留为排查指引(见下「现状」)。
- **原因**:登记本条时,Cubase **15** 刚进入测试矩阵,其插件扫描/沙箱进程模型与 WebView2 子进程(`msedgewebview2.exe`)如何相处没有实测数据。已知风险面三处:
  1. **user-data 目录跨进程冲突**。宿主把插件扫描放在独立 sandbox 进程,音频进程与扫描进程同时活着;两进程若拿到同一个 user-data 目录,WebView2 环境创建会失败。**已修**:目录名带 PID(`PlatformWebView::makeUserDataFolder`),跨进程唯一。原实现只有进程内自增后缀,不同进程都拿 `_0`。
  2. **user-data 目录可写性**。目录已从 `%TEMP%` 迁到 `%LOCALAPPDATA%\Synchain\SCVB\WebView2`(`%TEMP%` 会被 Storage Sense 在会话中途扫掉),并在编辑器构造期建目录 + 写探针,结果进诊断面板。
  3. **子进程链被宿主策略挡掉**。插件侧无法规避,只能让它**可见**:导航事件一次都没来时,兜底面板直接显示「WebView2 环境没起来」而不是「加载太慢」。
- **影响**:无(三条都已转成可诊断状态)。
- **缓解**:测试包内附 `诊断.ps1`(= `scripts/check-webview2.ps1`),一次查完运行时版本 / user-data 可写性 / 子进程是否在跑。
- **现状**:此后 Cubase 15 Pro 上多轮成品测试包(2026-08 下旬 – 2026-09-28)的编辑器都能正常开窗使用,上述三处都没有再出现;本条保留,作为「编辑器开不出来」时的排查指引。
- **彻底修复方向**:**JUCE 侧有一处上游限制须记住**:`juce_WebBrowserComponent_windows.cpp` 把 `CreateCoreWebView2EnvironmentWithOptions` 与 `CreateCoreWebView2Controller` 两个完成回调的 HRESULT 形参都写成**无名参数直接丢弃**,失败时既不抛也不通知客户端。故「环境为什么没起来」的确切 HRESULT 在 JUCE 8.0.8 下拿不到,只能靠「导航事件从未到达」判定这一类。若后续需要精确 HRESULT,得自己直连 loader 复现一次环境创建(需引 `<WebView2.h>`),或向上游提 patch。

## KI-3:`STATE_SCHEMA` 声明了 Input 侧 `uiGuideSeen` 的编码落点,而 `InputStateCodec` 没做

- **现象**:Input 首启引导的已读位 `ui.guide_seen` **不随工程持久化** —— 重开工程一律回 `false`。
- **原因**:`docs/STATE_SCHEMA.md`(**冻结文档**)第 100 / 154 行逐字写着 `InputStateCodec` 的 `CFGS` 尾扩 `u32 uiGuideSeen`,而实现里 `InputStateCodec` **严格等长校验、没有尾扩机制**,从来没编码过这个字段。属「冻结文档声明了、实现没做」——缺口自 [J81] 修宪写进文档时就存在。
- **影响**:**用户可见承诺不受影响**。跨工程的「不再显示」由系统级全局位 `guide_seen_global_input` 兜住([SL-258] 已真落盘,按侧分键);工程内的位只在本次会话有效,且换载工程时显式清零(不会把上个工程的位带过去)。至多是「同一工程重开后引导再弹一次」,而全局位已勾时根本不弹。
- **缓解**:无需用户操作。
- **彻底修复方向**:**SL-238** —— 二选一:① 给 `InputStateCodec` 加尾扩机制 + 测试后实装该字段;② 走 §5 契约流程把该字段从 `STATE_SCHEMA` 撤回。定性未决。

## KI-4:单轨渲染得到静音文件;替换式渲染会覆盖原素材(⚠ 用户数据)

- **现象**:对装了 SCVB Input 的**单条**人声轨做 Render in Place、Freeze 或单轨 stem 导出(这些渲染都会经过该轨的插件链),得到的是**静音**文件。如果宿主设置成用渲染结果**替换**原来的音频(替换式渲染),原素材就被这份静音结果替换掉了。
- **原因**:检测到健康的 SCVB Output 时,Input 会让本轨向下游输出静音(硬约束第 3 条),这条轨的声音改由 Output 在总线上求和后输出。单轨渲染只取这条轨自己的输出,所以是静音。
- **影响**:只渲染出一个静音文件时,重做即可;**替换式渲染会丢掉原素材**,是本条最要紧的后果。
- **缓解**:对**人声总线整体**导出(Cubase Export → Audio Mixdown、REAPER File → Render 等)。确实需要单轨素材时,先把这条轨上的 SCVB Input 旁路或移除再渲染,并且不要选「替换原音频」类选项;不确定时先备份工程和音频。
- **彻底修复方向**:无。这是「人声轨先、总线后」处理顺序(ADR-002)的直接后果,改掉静音通路就会破坏总线集中处理。

## KI-5:同一台机器同时开两个使用 SCVB 的工程,会互相抢 channel

- **现象**:同一台机器上同时开着两个使用 SCVB 的工程(两个 DAW,或同一个 DAW 的两个工程),而且两边用的是**同一个组**时,两边的 Input / Output 会落进同一个总线域:后开的一边可能报「channel 冲突」、第二个 Output 进入只读观察模式,不冲突的 Input 也可能连到另一个工程的 Output 上。
- **原因**:插件之间靠共享内存通信,共享内存段名只按组号(A–H)区分,不带工程标识(段名前缀 `SynchainSCVB.v1.` 是冻结契约,见 `docs/IPC_CONTRACT.md`)。
- **影响**:后开的工程得不到正确的平衡结果,两边的 channel 分配会互相干扰。
- **缓解**:同一时间只开一个使用 SCVB 的工程。确实需要同时开时,让两个工程用**不同的组**(八个组互相独立)。
- **彻底修复方向**:段名加入工程标识(documentToken)做隔离。改段名属于 IPC 布局改动,要升 abi 并把段名升 v2,v1 不做。

## KI-6:宿主停止调用 Output 后,人声约 5.5 秒无声,然后恢复成未平衡的原始声像

- **现象**:播放中宿主不经 bypass、直接停止调用 SCVB Output(Ableton Live 停用设备、FL Studio 的 smart disable 等)时,人声先**无声约 5.5 秒**,之后恢复成**未经平衡的原始声像**。宿主重新调用 Output 后,各轨按顺序逐条接回平衡结果。
- **原因**:Output 被停调时自己不会收到任何通知。Output 一侧有一个看门狗:自己的处理计数停住 **≥0.5 秒**、同时仍有在线的人声轨在写数据,就判定「停摆」并断开连接;Input 随后按硬约束第 3 条的 **5 秒滞回**切回直通。0.5 + 5 ≈ 5.5 秒。停止播放时各轨都不写数据,看门狗不会误判。
- **影响**:这 5.5 秒左右人声轨没有声音;之后听到的是未平衡的原始声像。
- **缓解**:想做 A/B 对比时,用 SCVB 面板上的轨道开关或输出开关,不要停用设备。FL Studio 用户请对 SCVB Output 所在的总线关掉 smart disable(SCVB 的总线输入本来就是静音的,很容易被误挂起)。
- **彻底修复方向**:暂无计划。5 秒滞回是为了防止短暂卡顿时在「静音 / 直通」之间反复切换(J12 / J32),缩短它会把这类抖动带回来。

## KI-7:rc 版本里,插件内的文档链接打开是 404(仅限首个正式版发布之前)

- **适用范围**:首个正式版发布之前的预发布版本(`v0.9.0-rc.N`)。首个正式版发布后本条自动失效,见「彻底修复方向」。
- **现象**:在 rc 版本的插件里点设置页「使用说明」一栏的「文档」按钮,或打开九条使用规则第 2、9 条里写的 DAW 兼容表地址,GitHub 显示 404。
- **原因**:插件里的这些地址固定指向仓库的 `prod` 分支(J149),而 `prod` 只在正式版发布时才前移(J163);首个正式版之前,`prod` 上还没有用户手册与 DAW 兼容表。rc 只前移 `staging` 分支,不动 `prod`。详见 [RELEASE.md](RELEASE.md) 的「`staging` 与 `prod` 两个分支」。
- **影响**:只影响插件里这几个链接,插件功能与音频不受影响。
- **缓解**:用这一版 GitHub Release 正文里的文档链接,或 zip 里 `INSTALL.txt` 的手册链接,两者都固定在本版的 tag 上,打得开;也可以直接在仓库里切到本版的 tag,打开 `docs/USER_GUIDE.zh-CN.md`(英文 `docs/USER_GUIDE.md`)与 `docs/DAW_COMPATIBILITY.md`。
- **彻底修复方向**:首个正式版发布、`prod` 前移之后,这些地址就有内容了 —— **已经装上的 rc 版本里的链接也随之恢复**(地址没变),不需要更新插件。用户已接受 rc 期间的 404(J163)。

## KI-8:在 DAW 里静音、独奏人声轨或拉它的推子,SCVB 的输出不跟着变

- **现象**:对装了 SCVB Input 的人声轨按 DAW 的静音(Mute)或独奏(Solo),或者拉这条轨的推子,总线上听到的这条人声不变:静音了它照样响,独奏别的轨时它也还在,推子拉到底也照样有声。Cubase 上实测如此(S1 路由 spike 的 C-10,见 [DAW_COMPATIBILITY.md](DAW_COMPATIBILITY.md) §1 脚注 1);其他宿主没有逐一验证。
- **原因**:Input 插在人声轨插件链的最后一格、推子之前(硬约束第 2 条;Cubase 要放在 pre-fader 区),在那里把这条轨的声音交给总线上的 Output;这条轨自己向下游只输出静音(硬约束第 3 条)。DAW 的静音、独奏与推子作用在插件链之后,改变的只是那份静音,不是 Output 收到的声音。
- **影响**:习惯用 DAW 的静音 / 独奏做 A/B 或单听某个声部时,会以为操作没生效;用推子调的音量不会出现在 SCVB 的输出里。
- **缓解**:在 SCVB 里操作。要把某一轨从 SCVB 的输出里去掉,关掉 Output 轨道页该轨的「ON」开关(关着的轨也不会被写自动化);想单听某个声部,就把其余轨的「ON」关掉。要改某一轨的音量,用 SCVB 的手动微调或轨道页,不要拉 DAW 推子。
- **彻底修复方向**:无。这是「在插件链末格接走、由总线上的 Output 统一输出」这一架构(ADR-002 / J45)的直接后果。

## KI-9:齐唱 / 加倍(double)段落的平衡估算有偏差

- **现象**:几条轨唱同一句、声音高度相似的段落(齐唱、加倍轨),分析给出的音量与左右平衡听起来可能不如其他段落准:这些段落合起来往往比预想的更响,左右也可能略偏。
- **原因**:分析按「各轨声音互不相关」估算叠加后的响度与左右能量(平衡算法的能量相加模型)。互不相关的声音叠在一起,能量按相加算是准的;高度相关的声音会相干叠加,实际比估算更响 —— 两条完全相同的声音放在同一位置,实际比估算响约 3 dB,相同的轨越多差得越多。SCVB 不存音频(只存每 10 ms 一帧的特征),分析时没法按真实波形复核。
- **影响**:只影响这类段落的平衡结果,不影响其他段落,也不影响音频通路本身。
- **缓解**:听完觉得这些段落不平衡,用手动微调(见用户手册「手动微调」)修正这几段;手动改过的段不会被之后的自动重分析覆盖。
- **彻底修复方向**:要按真实波形复核就得存音频,v1 按设计不存(ADR-007),留待以后再议。

## KI-10:波形页上建选区、选段与改分段只能用鼠标

- **适用范围**:`v0.9.0-rc.N`。计划在 v1.0.0 之前补上键盘做法(J178)。
- **现象**:在 Output 的波形页(「波形与分段」)上,下面几件事只能用鼠标或触控板做,键盘做不了:在时间标尺上拖出选区;在泳道上点选一段;拖动段边界;在泳道上双击分割一段或删掉一条边界。这一页上的其他控件(工具条按钮、缩放条、泳道滚动区等)都能用 Tab 键到达;已经有选区时,选区两端的手柄也能用 Tab 键到达,并可用 ← / → 微调;选中相邻两段之后按 Delete 合并,按 Esc 取消选择。
- **原因**:段与段边界是画在画布上的,不是能获得键盘焦点的独立控件;时间标尺同样只响应鼠标。
- **影响**:只用键盘操作时,在波形页上建不了选区、选不了段,也就用不了要先有选区或选中段的功能 —— 局部重采集 / 重分析、段检查器里改 pan / vol(用户手册「局部重采集 / 重分析」「手动微调」)。其他三页不受这一条影响。
- **缓解**:这几步用鼠标或触控板做。
- **彻底修复方向**:v1.0.0 之前补上键盘建选区、选段与移动段边界的做法(J178)。
