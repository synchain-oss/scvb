# SCVB 用户手册

SCVB 是由 [Synchain](https://synchain.ca) 主导的开源插件项目,源码与文档完全公开,欢迎在 [GPL-3.0-or-later](../LICENSE) 的条款下自由使用、修改与分发。如果它帮你省下了时间,也欢迎去 [synchain.ca](https://synchain.ca) 看看我们的其他产品 —— 用得顺手的话,把 Synchain 推荐给你的朋友和同事,就是对我们最好的支持。

SCVB(Synchain Vocal Balancer)是**一对**配套的 VST3 插件,用来给多人多声部的人声做自动声像与音量平衡:

- **SCVB Input** 插在每条人声轨上,负责采集;
- **SCVB Output** 插在人声总线上,负责分析、平衡、求和,并把结果写回 DAW 的自动化。

两个插件必须**同时安装、成对使用**。只装一个不会让你得到一条没有声音的轨道(见硬约束第 3 条),但也不会得到任何平衡结果。

同一个 zip 里还有第三个插件 **SCVB Monitor**,**可选**:一个只读窗口,用来看整组的声像与音量变化。它原样直通音频,没有任何自动化参数,也不会改变 Input 与 Output 的行为。

> **九条红字的改法**:本文件 `## 硬约束` 小节是这九条的**唯一真源**。它们另外还出现在 `docs/USER_GUIDE.md`、两份 README 的快速上手、以及插件 UI 的三语词条里,共 7 处。**任何一处都不许手抄** —— 改文案只改本小节(译文改 `docs/hard-rules.i18n.json`),然后跑 `node scripts/gen-hard-rules.mjs`,其余 6 处随生成物更新;`node scripts/gen-hard-rules.mjs --check` 是门禁。

## 硬约束

违反下面任何一条,得到的都不是"效果差一点",而是静音、声像位置错误或分析失效。插件首次启动时会把这九条完整弹一遍,你也可以在 Output 的**设置**页随时重看。

> ⚠️ **必读:SCVB 的九条使用规则,违反其中任何一条都会导致静音、声像位置错误或分析失效。**
>
> 1. **人声轨必须保持 DAW 原有路由,指向 SCVB Output 所在的总线。** 不要把人声轨改成直接送主输出,也不要绕开总线。(ADR-002)
> 2. **SCVB Input 必须插在人声轨插件链的最后一格;SCVB Output 必须插在总线的第一格。** 位置不对会破坏 DAW 的处理顺序假设;各宿主对这一格的具体叫法见 `https://github.com/synchain-oss/scvb/blob/prod/docs/DAW_COMPATIBILITY.md`。(ADR-002 / J45)
> 3. **只有在检测到健康的 SCVB Output 时,Input 才会向下游输出静音——这是设计行为,不是 bug。** 这条静音通路保住了 DAW 依赖图里"先人声轨、后总线"的排序,离线渲染与 REAPER 的预测性多线程下依然成立。**检测不到健康 Output 时(未装、未连上、对端已退出),Input 自动切回直通**,80ms ramp 过渡、5 秒滞回防抖(滞回只作用于"静音 → 直通"方向;"直通 → 静音"在确认健康后立即 80ms ramp),所以你不会因为只装了一个插件就得到一条没有声音的轨道。(ADR-002 / J12 + J32)
> 4. **人声轨与总线的宿主 pan 必须保持居中。** SCVB 内部用 equal-power pan,与宿主 pan law 无关;宿主 pan 不居中会叠加出错误声像。(ADR-010)
> 5. **每个 channel id 在同一个组内唯一,而同一条人声轨只能属于一个组。** 同组内两个 Input 抢同一个 channel 时,后来者会看到"channel 冲突"警告并且不会生效;不同组的同号 channel 是两条互不相干的通路。(ADR-002 / J66)
> 6. **同一个组同一时间只能有一个生效的 Output 实例。** 同组的第二个实例进入只读观察模式并显示警告;八个组(A–H)各自是独立的总线域,互不影响。(ADR-002 / J66)
> 7. **所有轨默认参与自动声像;立体声轨如需保留原有声像宽度与位置,请在轨道页关闭该轨的「参与自动声像」。** mono 源经 equal-power pan 摆位;stereo 源走 dual-pan + width 模型(pan = 弧中心,width = 张开度),关闭参与后保留你已有的声像宽度,不会被自动分配改写。(ADR-003 / J57 + J83)
> 8. **SCVB Output 不向 DAW 报告额外延迟。** 对齐靠时间线寻址完成,不要试图用 PDC(延迟补偿)去"修正"它。(ADR-002)
> 9. **看到"时间线缺口 / 重叠"警告时,不要继续导出。** 先按 `https://github.com/synchain-oss/scvb/blob/prod/docs/DAW_COMPATIBILITY.md` 的通用坑清单排查路由,警告计数不归零就说明有轨的音频没被正确接管。

## 安装

所有东西都在一个 zip 里:`SCVB-v<版本号>-win64.zip`,内含三个插件:

| 插件 | 放在哪里 | 要不要装 |
|---|---|---|
| **SCVB Input** | 每条人声轨插件链的最后一格 | 必装 |
| **SCVB Output** | 人声总线的第一格 | 必装 |
| **SCVB Monitor** | 任意一条轨(它原样直通音频) | 可选 —— 用来看整组情况的只读窗口 |

### 下载与校验

1. 从 [Releases 页](https://github.com/synchain-oss/scvb/releases)下载 `SCVB-v<版本号>-win64.zip` 与对应的 `.sha256`。
2. 校验 zip。在下载目录打开 PowerShell,运行 `Get-FileHash .\SCVB-v<版本号>-win64.zip -Algorithm SHA256`,结果必须与 Release 正文里的 SHA-256 一致(那个值由 CI 产出,以它为准)。**对不上就不要安装,并告诉我们。**

### 解除锁定(插件未做代码签名)

SCVB 没有做代码签名,所以 Windows 与浏览器会把它当作「未知发布者」的文件:

- **浏览器可能拦下载**(提示「不常下载」或「未知发布者」)。SHA-256 校验一致的话,选择保留文件 —— Microsoft Edge 里是 **…** → **保留** → **显示更多** → **仍然保留**。
- **解压之前先去掉「来自网络」的标记。** 带标记的 zip 解压出来的每个文件都会带上同样的标记。右键 zip → **属性** → **常规** 页勾选 **解除锁定** → **确定**。如果没有「解除锁定」这个勾选框,说明文件没带标记,不用做任何事。PowerShell 的等价命令是 `Unblock-File .\SCVB-v<版本号>-win64.zip`。

### 复制插件

1. 解压,把 `SCVB Input.vst3`、`SCVB Output.vst3` 与(需要的话)`SCVB Monitor.vst3` **整个 bundle 文件夹**复制到 `C:\Program Files\Common Files\VST3\`(Windows 会要求管理员权限)。
2. 在 DAW 里重新扫描插件。

**所有 SCVB 插件一起升级。** Input 与 Output 共用同一个版本号。两侧的共享内存协议版本不同时会刻意拒绝连接;即便能连上,「旧 Input + 新 Output」(或反过来)的混装也不受支持(新 Output 配旧 Input 时,离线渲染的人声可能被叠加两次)。

## 5 分钟上手

### 建一条人声总线

在 DAW 里新建一条立体声总线(group / bus / submix,叫法随宿主),把所有要参与平衡的人声轨输出指向它。**人声轨的路由到此为止就不要再动了**(硬约束 1)。

### 装两个插件

在**每条**人声轨的插件链**最后一格**放一个 SCVB Input;在总线的**第一格**放一个 SCVB Output(硬约束 2)。逐宿主的具体操作见 [DAW_COMPATIBILITY.md](DAW_COMPATIBILITY.md)。

### 分配 channel 与组

打开每个 Input,给它选一个 channel id。同一个组里 channel id 不能重复(硬约束 5)。组选择器是 A–H 八个胶囊,默认 A;单个乐曲工程通常用不到第二个组,组是给"同一个 DAW 工程里有多套互不相干的人声总线"准备的。Output 侧在 Tab1 选同一个组。

**轨道名自动填入**:Input 选好 channel、连上 Output 之后,Output 轨道页这一轨的名称会自动取 DAW 里这条人声轨的轨道名(超过 24 个字符的部分截掉);在 DAW 里改轨道名,这里跟着改。你在轨道页**亲手改过**名称的轨不再跟随 DAW 改名;把名称**清空**就回到自动(Input 在线时立刻填回当前轨道名)。Input 断开(改成未分配、删掉那条轨等;判断口径与界面上的「未连接」相同)后,名称保留最后一次的轨道名。宿主不提供轨道名时不会自动填,这一格保持原样(从没填过就显示占位名)。

### 采集

在 Output 打开**采集**开关,然后正常播放走带。采集只在"开关 ON **且** transport 在播放"时写入;播放到哪儿就采到哪儿,重播同一段会覆盖旧数据。SCVB **不存音频**,只存每 10ms 一帧的特征(见"会话与文件")。

### 分析

采集覆盖到整首之后点**分析**。分析会做人声检测(VAD)、切分段落、算段响度,然后生成每轨的 pan / vol 曲线。阈值和分段灵敏度可以随时调、实时预览,**不需要重新采集**,因为采集存下来的是特征而不是音频或者判定结果。

**只有此刻连着 Input 的通道参与分析**(与界面上「未连接」同一个判断)。一条轨改到别的通道、或者它的 Input 被删掉 / 停用之后,原通道采到的数据仍然保留,但分析不再计入它(断开期间拖 VAD / 分段滑杆触发的自动重分段也不会更新它的段);Input 连回来,下一次分析它自动回来。判断口径与界面一致:Input 的心跳超过 2 秒没更新(例如宿主卡住)时也算未连接。所选范围里有数据的通道都没连上时,这次分析不会执行(不会拿旧数据去算):总览页「分析」下方的影响预览行会改显示原因,波形与分段页、设置页的重分析按钮也会给出提示。

### 输出

打开**输出**开关。这时总线上听到的就是平衡后的结果:每轨按曲线取 gain/pan,求和后替换总线输入。第一次打开开关会有一条一次性确认条,说明打开后会发生什么;**点确认条上的「知道了,开始」之前只试听、不写宿主自动化**(页脚也不会显示「写入自动化 …」),点「撤销(回溯到跟随宿主)」则关回跟随宿主。「第一次」按每次打开插件窗口算:确认条出过一次之后,本窗口里再关、再开输出开关不会再出,开了就写。确认条挂着时关掉插件窗口再打开,确认条还在,照样要点「知道了,开始」。

### 写自动化

把 DAW 的自动化模式设成 **Write** 或 **Latch**,再播一遍。SCVB Output 会把当前版本的曲线按播放位置写成宿主自动化(15 轨 × pan/vol,共 30 条)。写完把自动化模式切回 Read,插件就忠实跟随你 DAW 里的自动化。在这之后,你可以在 DAW 里对自动化进行手动微调,除非再 write 一次,否则不会被插件覆盖。插件会忠实地复现自动化轨道的结果。

Input 是单页:channel 选择、组选择、连接状态、电平、直通/静音状态、就地 gain 开关。**配置的真源在 Output**,Input 上显示与可调的值实际读写的是 Output 的 state(经控制面 IPC)。

首次启动 Output 时依次是:语言选择卡 → **九条红字页** → "要不要花一分钟快速了解界面?" → 交互式引导 tour。

## 作用范围(Range)

总览页的 RANGE 卡决定采集与输出引擎在时间线的哪一段上工作,三档:**全曲**(默认,播放到哪采到哪)、**循环区**(跟随 DAW 的循环区)、**手动**(自己定起止)。

手动档:

- 起止两个输入框用 `分:秒.毫秒`;下面一行同时显示这段范围落在**第几小节第几拍**(如「小节 33.1 → 49.1」),**−4 / +4** 把终点前后挪 **4 小节**。
- 小节是按宿主报的**速度、拍号和当前拍位置**换算的。插件只能读到宿主**此刻**的速度,读不到整张速度表,所以:
  - **恒速、拍号不变**的工程:小节是准的,下面不显示提示;
  - **有变速**:没播放过的地方按最近读到的速度估算,提示「小节为估算值,播放该区域后校准」;把起点、终点那一带各播一下(或把播放头停在那儿),就按宿主报的实际位置校准,提示随之消失;
  - **有变拍号**:小节号取决于整段的拍号历史,插件读不到,提示「拍号有变化,小节号为估算值」,播放也校准不了,以 DAW 标尺为准;
  - **宿主不报速度**(或插件窗口刚打开、还没收到):只按秒显示并提示,−4 / +4 挪 4 秒。
- 插件要**亲眼见到**变速才知道有变速:播放头经过变速点、或停在变速之后的位置,都算见到;在那之前它会把整段当成恒速换算,而且不提示。
- 在 DAW 里**改了速度**之后,只要播放头所在的那一点(或播放头随后经过、停到的、之前播放过的地方)因此对不上了,插件就会把之前记下的全部作废、从头观察;改动落在这次还没播放过的地方时,那里本来就只是按最近速度推算的值。
- 停止走带时沿用最后一次读到的速度。这些速度信息只在插件窗口开着时记在内存里,不存进工程;关掉窗口再打开会重新观察。

## 采集

- **写入条件**:采集开关 ON **且** transport 正在播放。停止走带就停止写入。
- **重播语义**:按时间线寻址合并,重播同一区间会用新数据覆盖旧数据。想重录某一段,把那一段再播一遍就行。
- **存的是特征不是音频**:每 10ms 一帧的 K 加权 mean-square + peak + VAD 连续后验。所以工程体积可控,而且阈值可以离线随意调整。
- **覆盖度**:没采到的区间在波形页显示为未采集,不会被伪造成静音。有需要时可以直接补录那一段。

## 分析

- **VAD**:能量域双阈值 + 滞回 + hangover + 前后 padding,默认配置偏保守。阈值与灵敏度可拖动实时预览:拖动时泳道顶部的绿色标注带与绿色点划线会即时显示**当前参数下每条轨哪里算有声、长乐句在哪里切**(只是预览,段表不动;边播边采集时绿带暂不跟着拖动变,点划线照变,用的是最多 1 秒前的采集数据)。松手 300ms 后才真正重分段 —— 最终段表还会在**其他轨**的边界处再切开,所以段数可以比预览里的多。**这五项与 Tab1 的过渡时间都随工程保存** —— 存盘时是多少,重开工程就还是多少(自 v5.6.15 起;[SL-416])。
- **分段**:能量谷检测 + 最小段长(波形页 **MIN SEG**,**50–2000 ms**,默认 120 ms)+ 换气容忍。短于它的自动段会被丢掉,或并入**时间相接的**相邻段;手动段不受影响。**整条时间线重新分析后,段表里不再有「短于它、且存在相接自动邻段」的自动段**;两侧都不相接的孤立短段按设计保留(选区或范围档重分析在窗边裁出的残段,以及邻段因与手动段冲突而整条落选后剩下的孤段)。**这一组设置随工程保存**(分段模式 / 灵敏度 / 最小段长三项自 v5.6.14 起落盘,见 `docs/contract-changes/20260914-sl411-segmentation-persist.md`):存盘时是多少,重开工程就还是多少,**最短段长与灵敏度按它跑**;**分段方式在 v1 里是保留位** —— 界面上没有这个下拉(**从来就没有**,不是这一版藏起来的),分析引擎也不消费它(恒按「能量谷检测」走),落盘只保证它不丢(`vad_only` 那一档留待接线时启用,见 `docs/contract-changes/20260914-sl413-seg-mode-reserved.md`)。
- **段响度口径**:设置页可选 **K 加权段积分(默认)/ RMS / 峰值 dBFS**,改完需要重新分析。
- **中心槽策略**:多轨争抢中心位时的兜底规则,可选**按优先级排队(默认)/ 主唱独占 / 均分微偏**,同样是"改后需重分析"。
- **Lead Select 进入分析**:总览页 Lead Select 选中的轨,重新分析时按主唱处理 —— 放在正中、不占其余声部的位置,其余声部围绕它左右排开,音量平衡也把它算作居中的那一轨。**在插件里选好直接重新分析即可,不用重播**:在插件界面上改的 Lead Select 不算自动化(撤销 / 重做写回的值、打开工程时恢复的值也一样),重新分析会把**点分析那一刻**的值用于整条时间线 —— 改完先试听一段再分析,结果也一样。Lead Select 也可以被 DAW 自动化(每句换一个主唱也行):Output 在**播放经过时**记下 DAW 写进来的值,重新分析时这些段落照记录走,自动化还没播到的地方用点分析那一刻的值 —— 所以写了或改了自动化之后,要**把自动化所在的段落播一遍再重新分析**。在 DAW 自己的参数面板或控制器上改 Lead Select,也按自动化算(插件分不出它们与自动化回放)。一个边角:Output 只看得到 Lead Select 的值**变了**的那一刻是谁改的 —— 自动化播到的值若与此刻的值相同,就没有一次改动,那一段不算自动化,按点分析那一刻的值排布。典型是自动化开头那段的值恰好等于播放前的值(比如都是 0),而播放头最后停在自动化是另一个值的地方:开头那段就会按停带位置的值走。点分析前把播放头停在自动化是开头那个值的地方(通常是歌曲开头),或在插件里把 Lead Select 选成那个值,再重新分析。没重新分析之前,选中的轨照旧被实时拉到正中,只是其余声部还是原来的排布。
- **拖阈值时不会动你手改过的段**:松手 300ms 后只有 `origin=auto` 且未锁定的段会被改写,手动编辑过或锁定的段逐字节不变,diff 首行会告诉你保留了几处。

## 手动微调

在波形页点选一个段,用段检查器改它的 pan / vol:

- 手动改过的段标记 `origin=user_edited`,新建的段标记 `origin=user_created`;
- 可以额外加 `locked`;
- **自动重分析不会覆盖这两类段**,除非你显式要求对它们重新识别;
- **上了锁的段连「重新识别(含手动段)」也动不了** —— 锁是第二道闸,得你自己逐段解锁才摘得掉。

**拖动段边界会吸附到能量谷**(按住 Alt 拖就不吸):手柄离某个能量谷在 6 像素以内时直接落到谷上,手柄亮成琥珀色。这里的「能量谷」是响度包络(平滑 50 ms)里的低点,**两侧都要回升超过 6 dB** 才算 —— 这是默认分段灵敏度下的门槛,灵敏度越高门槛越低(3–12 dB)。典型是句与句之间的停顿和较深的换气;没采集到的空当不算谷。所以如果某处拖过去没吸,多半是那里两侧回升不到这个数。缩得很远、这一轨在一屏里已采集的素材超过约 1 小时时不吸附。

轨道页对某个维度**冻结**,等于宣布"这个维度我手动接管":write 时该维度以平直线写入自动化,之后你在 DAW 里怎么画都不会被引擎盖掉。优先级链是:**宿主自动化 > 冻结的手动值 > 手动微调 > 引擎分析曲线**。

冻结是**可逆的临时接管**:冻结期间调的值只存在参数面上,分析曲线原封不动 —— **解冻后该维度立刻回到引擎分析曲线继续运动**,重新分析也照常更新它。冻结中调整**进插件的撤销栈**(轨道页每轨的启用 / 名称 / 优先级 / 主唱锁定 / 音量豁免 / 参与自动声像 / 配对 / 冻结 / 宽度,以及总览页的全局 Width、MS Balance、Lead Select 也都进):按 Ctrl+Z 撤掉的就是刚才那下旋钮。未冻结时第一次拖某轨的音量卡箍(把这条轨交给手动),一次 Ctrl+Z 会连冻结开关一起撤回,旋钮与声音都回到拖之前。撤销写回旧值走的是与你手动拧旋钮同一条宿主通路,所以宿主自动化照样说了算:该参数有自动化且宿主处于读取档时,播放或定位会按自动化把值改回;处于写入 / 触动 / 锁存档且在走带时,这次撤销会被录成自动化,与手动拧一下相同;没有自动化时,插件的撤销就是回退它的办法。按住旋钮或滑杆拖动时按 Ctrl+Z,会先取消这次拖动(回到按下时的值)再撤销。

## 局部重采集 / 重分析

失效与重算的单位是**(轨道 × 时间区间)**,**绝不触碰其他区间已有的结果**。在波形页框出选区,然后:

- **重采集**:进入布防态(三处都会显示布防 badge),并**自动替你打开「01 采集」**。此后播放到该区间时重写特征 —— 只有 **{勾选的轨} × {选区}** 之内的部分会被改写,选区外与没勾的轨一个字节都不动。勾了「区域外自动停止」时,播放头越过选区右边界即自动撤防,并把「01 采集」恢复成布防前的状态(布防前本来就开着的会保持开);不勾就一直布防着,方便对同一段循环重录几条。布防期间如果打开了输出开关会有琥珀警告。
  撤防之后(你手动关掉,或越过右边界自动停),右下角会弹一条提示「已重采集 X.Xs,建议重分析该范围」:X.X 是这次布防期间**播放头在选区里真正走过的时长**(采集关着的那几段不算,同一段循环录几遍只算一遍);点「立即重分析」会跳到波形页,对**从最早到最晚重采到的那一段时间 × 布防过的轨**重跑分析(中途挪过选区、或跳着播过几段时,中间没重采的部分也会一起重跑 —— 那里特征没变,重跑只重算自动段,手动段照旧不动),点 ✕ 则只关掉提示。布防后一下都没播就撤防不会弹。这个秒数是界面按播放头推算的:编辑器窗口关着的那段时间界面看不到播放头,不计入。
- **重分析**:只对选区重跑分析,其余区间的段与曲线原样保留。

## 版本

有 **2 个版本槽**,每个版本存一整套曲线 + 配置:

- 版本 chip 在 header,四个 tab 都看得到;双击可以就地重命名(≤16 字符,清空回落 `V{n}`);
- **复制到…** 把当前版本整套复制进另一个槽,是 state 内的复制,**零自动化污染**;
- 切换版本**不是**自动化参数(否则 write 会把它自己录进自动化);
- 每个版本有自己的一整套 pan/vol/width 自动化参数,写自动化时写的是**当前版本**那一套。

## 把结果写进 DAW

1. 确认输出开关 ON;
2. DAW 的自动化模式设为 **Write** 或 **Latch**;
3. 播放要写的区间(Range 决定引擎作用范围:跟随 / DAW 循环 / 手动区间);
4. 写完切回 Read。

要点:

- 引擎只打印 **30 条**(15 轨 × pan/vol)。width / MS Balance / Lead Select 你可以自己自动化,引擎不打印它们,也不会去改写它们 —— **这三条始终以你 DAW 里的值为准**。
- 输出开关 **ON** 时,那 30 条的 DSP 直接用引擎值(参数只是对外的打印头);**OFF** 时 DSP 用宿主参数值。
- 切版本、复制版本、改段值、关输出开关,**都不会**产生宿主自动化事件。
- 重开一个 `output_enabled=ON` 的工程时会有加载守卫横幅:在你点"继续写入自动化"之前,插件只备而不发,**一个 gesture 都不会写出去**。把输出开关关掉也会解除这道守卫:之后再手动打开,就和平常手动打开一样 —— 本窗口里还没出过「输出」一节说的那条确认条时会出确认条,点「知道了,开始」之后播放一进已分析区间才开始写;出过的话开了就写。宿主重新载入一份输出开关为开的插件状态时(例如带插件状态的 DAW 撤销、A/B 对比、载入预设),也算重开了一次工程:横幅会再出现,需要再确认。
- 逐 DAW 的坑(Cubase 车道位置、REAPER 关 GUI 不写、Pro Tools 循环只录第一遍等)见 [DAW_COMPATIBILITY.md](DAW_COMPATIBILITY.md)。

## Pan 曲线编辑器

x 轴 = pan 角度 [-100, +100],y 轴 = 增益 dB。点类型有 **bell / shelf / cut** 三种,带 Q,插值方式与 EQ 曲线同构。它描述的是"某个声像位置上的增益修正",配合自动分配用来压制或抬升特定角域。你可以理解为是一个 EQ,不过横坐标不是频率而是角度。

和 EQ 一样,拖动时就能听到变化:拖点、拨 Q 滑杆、滚轮调 Q,声音都会实时跟着变(最多每秒更新 20 次,每次 30 ms 交叉淡入)。拖动过程只是预览,**松手那一下**(Q 滑杆与滚轮是停手片刻)才会存进工程、记成**一条**撤销步;预览不影响打印出来的自动化、Monitor 显示和分析用的左右平衡。

## 期望宽度 Width

Width 是**几何角度缩放** —— 把分配到的角度乘以一个系数,读数以角度显示(`±{θ}°`,`θ = round(width% × 0.6)`,所以 0 / 100 / 150% 对应 0° / 60° / 90°)。

**为什么不用 M/S 拉宽**:M/S 拉宽在 width > 1 时会让幅度声像源产生极性翻转,单声道兼容性直接崩。几何角度缩放没有这个问题。

对 stereo 源,width 是 dual-pan 模型里的**张开度**(pan = 弧中心),width=0 收成 mono。

## 会话与文件

- **分段 / 区间 / 2 版曲线 + 配置**(几百 KB 量级)存在 Output 的 state 里,随工程走。
- **特征流**压缩后**内嵌在 state 里**。本版**不提供外置存储**:特征不会写到工程外的目录,设置页也不再显示"存储状态"这一行(出厂态恒内嵌,**与 8MB 无关**)。
- 工程另存 / 拷到别的机器时特征跟着工程走。早期版本把特征写到外部目录的工程仍能打开并照常读回(那一路读路径保留了;打开时仍会在该目录写一个 `owner.lock` 所有权标记),**保存一次之后特征收回内嵌、外部那份目录被回收**——这一步**不可逆**,工程体积也随之变大;那份外部文件不在时特征无法恢复(分段与曲线不受影响),重新采集即可。
- Input 的 state 只有 channel id + UI 偏好;**配置的唯一真源永远是 Output**。

## 隐私与本机文件

**SCVB 不联网。** 三个插件都不上传、不下载任何东西:没有更新检查、没有使用统计、没有账号、没有授权服务器。界面从编进插件里的文件加载,字体也在里面。Input、Output、Monitor 之间只通过这台电脑上的共享内存通信。只有两个链接会打开网页,而且要你点了才会打开:说明文档链接,以及 WebView2 运行时缺失时出现的「安装 WebView2」链接。两者都在你的默认浏览器里打开,不在插件窗口里。(绘制界面的 Microsoft Edge WebView2 运行时是 Windows 的组件,由微软负责更新;SCVB 不改变它的行为。)

**SCVB 会写到磁盘上的东西:**

- **你的工程。** 设置、分段、曲线和采集到的特征由 DAW 存进工程文件,和其他插件的状态一样。
- **`%APPDATA%\Synchain\SCVB\ui-defaults.settings`** —— 几项跨工程的偏好:你选的界面语言、Output 界面的缩放比例、是否已经看过首启引导和导览。
- **`%LOCALAPPDATA%\Synchain\SCVB\WebView2\`** —— 绘制界面的内嵌浏览器的工作目录(缓存与设置),每个插件一个子目录。
- **`%APPDATA%\Synchain\SCVB\sessions\`** —— 只有早期版本保存、把特征存在工程外的工程才会用到(见上面「会话与文件」)。本版不会在那里新建目录。
- **导出的建议表 `.csv`** —— 只在你导出时写,位置由你选。

SCVB 不写日志文件。诊断信息只发到 Windows 调试输出,要用调试工具才看得到。

想清掉偏好和浏览器缓存:先关掉 DAW,再删除上面两个 `Synchain\SCVB` 目录。如果还有早期版本的工程在用 `sessions`,请保留这个子目录。

## 故障排查

| 现象 | 可能原因 | 怎么办 |
|---|---|---|
| **顶部红 pill + 红横幅"版本不匹配"** | 只更新了两个插件中的一个 | SCVB 拒绝半兼容连接。把 Input 与 Output 一起升到同一版本 |
| **人声突然变成未平衡的原始声像** | 宿主停调了 Output(Live 设备停用 / FL smart disable) | SCVB 已自动转直通兜底,~5.5s 恢复。**FL Studio 用户:请对 SCVB Output 所在的总线关闭 smart disable** —— FL 依"输入静音"判定挂起插件,而 SCVB 总线输入恒为静音,特别容易被误挂起。逐宿主说法见 [DAW_COMPATIBILITY.md](DAW_COMPATIBILITY.md) |
| **某条人声轨没声音** | 该轨 Input 连上了健康 Output,但 Output 侧没拿到它的数据(channel 没选 / 组选错 / channel 冲突) | 检查该 Input 的 channel 与组;看 Output 轨道页该轨是否在线 |
| **装了 Input 就整轨没声音** | 不应该发生 | 检测不到健康 Output 时 Input 自动直通(硬约束 3)。若该轨确实没有声音,收集设置页"复制诊断信息"的输出并提 issue |
| **"channel 冲突"警告** | 同组内两个 Input 抢同一个 channel(打开工程时通道已被占用也会提示) | 改其中一个的 channel id,或把它换到别的组。占用的那个释放通道(删轨或改号)后,等着的那个约一秒内会自己接上 |
| **"组 X 已有主 Output,本实例只读观察"** | 同组已经有一个生效的 Output | 一个组只能有一个生效 Output(硬约束 6)。删掉多余的那个,或把它换到别的组 |
| **点通道卡 / 切组后弹出"未能连接:插件间通信用的内存段打不开"** | Input 没能打开或建立它与 Output 通信用的共享内存段(例如同名的段是别的 SCVB 版本建的) | 再点一次;仍不行就重启宿主,并确认同一台机器上没有开着装了其他版本 SCVB 的 DAW。换通道时出现的话,本轨仍留在原来的通道上照常工作 |
| **"时间线缺口 / 重叠"警告计数上涨** | 人声轨路由被改过 / 有轨没被接管 | **先别导出**(硬约束 9)。按 [DAW_COMPATIBILITY.md](DAW_COMPATIBILITY.md) 的通用坑清单排查路由 |
| **声像整体偏了** | 人声轨或总线的宿主 pan 没居中 | 把宿主 pan 全部回中(硬约束 4) |
| **导出的音频和实时听到的不一样** | 离线渲染下的路由/顺序问题 | 时间线寻址在离线渲染下同样成立;若仍不一致,记下 DAW 与版本提 issue |
| **write 没录上** | 自动化模式不对 / 该 DAW 的已知坑 | 确认 Write 或 Latch;REAPER 注意别关插件 GUI;见 [DAW_COMPATIBILITY.md](DAW_COMPATIBILITY.md) |
| **某轨被禁用,提示采样率不一致** | 该轨采样率与 Output 不同 | 统一工程采样率 |

## FAQ

**能只装 Output 吗?** 不能。没有 Input 就没有任何轨道数据。

**只装了 Input 会怎样?** 那条轨保持直通,不会没有声音(硬约束 3),但也不会有任何平衡。

**为什么参数不能再加?** 自动化参数面已冻结在 **123 个**(宿主可见 124),Ableton Live 的 128 上限只剩 4 的余量,而 Logic 按索引识别参数 —— 增删一个就会打乱所有既有工程里的自动化。新需求一律走 state。

**能超过 15 轨吗?** v1 不能,每组 15 轨。真的需要更多可以用第二个组(独立总线域),但两组之间不做联合平衡。

**支持 macOS 吗?** v1 只有 Windows x64 / VST3。后续会考虑编译 mac 版本。

**分析结果不满意能手改吗?** 能,见"手动微调";改过的段自动重分析不会覆盖。

**改了 VAD 阈值要重新采集吗?** 不用。存的是连续特征,阈值随时可调、实时预览。

## 已知限制与 v2 路线

完整清单见 `docs/KNOWN_ISSUES.md`。要点:

- 每组 15 轨上限、2 个版本槽;
- 每组同一时间只有一个生效的 Output;
- **同一台电脑上同一时间只开一个使用 SCVB 的工程。** 插件之间只按组(A–H)互相识别,不区分工程;同时开着的两个工程(两个 DAW,或同一个 DAW 的两个工程)如果用了同一个组,就会落进同一条总线、互相抢 channel。确实要同时开,就让两个工程用不同的组。详见 `docs/KNOWN_ISSUES.md` 的 KI-5;
- Output 不报告额外延迟(设计如此,不是限制);
- run 切换时旧 run 尾部 ≤40ms 可能漏采,补播即复原;
- Input 侧只做就地 gain,不做就地 pan(否则会和 Output 的 dual-pan 双重处理);
- v2 方向:精确模式 VAD(Silero)、更多平台。
