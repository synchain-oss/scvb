## 变更内容

裁决 **[J85]「冻结语义修订」**:`setTrackManual` 从「一条通道」拆成**两条通道**,按调用时该维度的
`freeze` 位分流:

| 通道 | 触发条件 | 写入面 | `replacedSegments` / `replacedLocked` | 撤销 |
|---|---|---|---|---|
| **冻结通道** | 该维度 `freeze` 对应位 = 1 | **只**写当前激活版本对应的 `v{v}_t{t:02d}_pan` / `_vol` 参数(带 gesture)。**曲线真身一个字节不动** | 恒 **0**(没有任何段被替换) | **否**(无 CRVS 变更,不入插件 UndoManager) |
| **手动接管通道** | 该维度 `freeze` 对应位 = 0 | 写全时限单段常值(04 §1.5 方案 A,`origin=user_edited`)**+** 参数面(#87 起) | 如实回替换前的段数 / 锁定段数 | **是**(仅回滚曲线真身,参数面不回滚 —— #87 裁定①) |

与现行契约文字的冲突,逐条列明:

| 契约原文(改前) | 冲突点 |
|---|---|
| §1.16 语义「**编码 = 04 §1.5 方案 A**:向当前激活版本该轨曲线写入**覆盖全时间线的单段常值**…… 写入常值段之后**追加**把同一个值写进…… 参数」 | 冻结通道**不再写常值段**,只写参数面 |
| §1.16 返回「`replacedSegments`/`replacedLocked` 供 UI 一次性确认条显示计数」 | 冻结通道恒 0(如实统计,因为确实没替换) |
| §1.16 撤销「**是**(仅回滚曲线真身)」 | 冻结通道**不入撤销栈**(见下「为什么冻结通道不入撤销栈」) |
| §1.16「重分析按 ADR-008 v1.1 不覆盖它」 | 冻结通道不再产生 `origin=user` 段,这条只对手动接管通道成立 |
| §1.13「轨 `pan`/`vol` 手动值 —— 走 `setTrackManual`(§1.16)的**曲线真身写入**」 | 冻结通道不走曲线真身 |

## 为什么必须改(不改就等于「一次冻结即永久锁死」)

用户 v5.3 A2 实测:**冻结某轨 pan 调了个值,解冻后 pan 永远停在冻结时的那个值,重新分析也不动。**
三条串起来才成立,缺一条现象都不出现:

1. 冻结中调整走 `setTrackManual`,它把静态值**整表烘焙**进曲线真身(单段全时限常值,`t1 = 1<<40` 哨兵,
   `origin=user_edited`);
2. 解冻后 `DspArbiter::processBlock` 引擎权威分支**回读曲线**(`src/core/engine/DspArbiter.cpp` §2.3),
   读到的仍是那条常值段;
3. 再分析按 **ADR-008 v1.1** 不覆盖 `origin=user` 段 → 那条常值段永远不会被重算掉。

冻结按定义是**可逆的临时接管**(`PARAMETERS.md` §freeze:「引擎不驱动、host/手动权威」),
「解冻即回引擎分析曲线继续运动」是它的语义本身,不是附加要求。旧实现让一次临时接管把曲线**永久**
改写了 —— 这不是参数取值问题,是通道选错了面。

契约自身其实指向这个修法:§1.16 开篇就把本函数定义为「**冻结(freeze 对应位=1)时的手动静态值**」,
而冻结维度的取值仲裁与打印器读的都是**参数面**(#68 / J78 / #87 已逐条确认)。既然冻结维度上没有任何
读者会去看曲线,写曲线就只剩副作用。

## 四条附带裁定

### 裁定① 冻结通道不入撤销栈(§1.16「撤销」行按通道分叉)

冻结通道跳过 `commitCrvsTransaction`,于是它**一步都不往 UndoManager 里压**。

这是有意的,但代价必须写明:用户在冻结态调了 pan 再按 Ctrl+Z,弹掉的是**上一笔不相干的 CRVS 事务**
(比如更早的一次段编辑),用户看到的变化和刚做的操作毫无关系。这比 #87 记的「冻结维度上撤销在听感上
无效」更靠前一步 —— 那条是「压了一步但听不出来」,现在是「压根没有这一步」。

不改成「压一个空事务」是刻意的:压一个什么都不还原的 undo 步,只会让 Ctrl+Z 变成「按一下没反应、
再按一下跳掉一笔旧编辑」,比直接不压更难解释。冻结通道**本来就没有可回滚的曲线状态** —— 它唯一改的是
自动化参数,而 §0.9 已明确「自动化参数不入插件 UndoManager」(插件自己回滚宿主的自动化面会与宿主的
撤销栈打架)。若将来要让冻结中调整也可撤销,唯一正路是走**宿主 gesture**,不是插件 undo。

### 裁定② 冻结通道的 `replacedSegments` / `replacedLocked` 恒 0

如实统计(PR#55 建议⑤同口径)。UI 的一次性确认条按这两个数显示「将替换 N 段(含 L 个锁定段)」——
冻结通道一段都没替换,报一个没发生的替换数就是骗用户。

**连带的 UI 确认条 —— 用户裁定 2026-08-27:方案 A「冻结通道不弹」**(本 PR 已落地)。

`tracks.manualOverwriteConfirm` 写的是「将以固定值替换该轨(当前版本)的全部分段结果,可撤销」。
对**冻结**通道这两句都不成立(不替换任何段、不入撤销栈)—— 拿一条关于「替换全部、可撤销」的警告
去拦一次「只改了个旋钮值」的操作,是在吓唬用户。**故冻结维度的手动写入直接执行,不弹确认条**;
未冻结的手动接管通道**照旧弹**(那一路确实会把整条分析曲线整表压成常值段,是真正需要用户点头的
破坏性操作)。

- **与 05 §2.2 R3 不冲突**:R3 的「**无条件**」原指「删掉 `origin=auto` 前置条件」(纯 `user_edited`
  轨同样要弹),不是「连不会替换段的通道也要弹」。
- **i18n 未改**:三语文案对未冻结通道原样成立,不需要分叉文案,`gen-hard-rules` / `check-i18n` 不受影响。
- **实现** = `web/output/tab-tracks.js` 的纯函数 `needsManualConfirm(freeze, dim, confirmed)`,
  `requestManual` 是唯一调用点。**逐维**判定(只冻 pan 时拖 vol 仍要弹);「每轨每会话一次」
  (`manualConfirmed`)优先级最高。冒烟对「冻结不弹 / 未冻结弹 / 逐维 / 已确认过」四组共 7 条断言,
  并有源码级断言钉住 `requestManual` 必须走这个判定。

### 裁定③ §2.8 `reason:"trackManual"` 照发,枚举闭合不受影响

冻结通道虽然没改段表,`handleSetTrackManual` 仍按契约回推该轨段表(`reason:"trackManual"`)。理由:
① §2.8 的 reason 枚举是**闭合**的,「改动段表的函数都必须落在某个 reason 上」不等于「没改动就不许发」;
② UI 用这一帧作为「本次写入已落地」的信号来清本地乐观值,不发会让乐观值挂死。
载荷内容 = 该轨**当前**(未变的)完整段表,形状与字段一字未改。

### 裁定④ 参数面帧与段表帧必须同拍发

`handleSetTrackManual` 在 `emitSegments` **之前**同步补一次 `emitParams(false)`。

不补就有一拍回弹:`emitSegments` 是同步发的,而 `scvb.params` 平时挂在 25Hz 的 `emitTick` 上;UI 收到
段表帧后按约定丢掉本地乐观值,而冻结通道的新值只在参数面上、还没发出来 —— 这一帧渲染时读到的是**旧**
参数值,旋钮先弹回旧值、最多 40ms 后才跳到新值。`emitParams` 自带 diff 门(值没变不发),不会产生
重复帧。`web-preview` 的 mock 桥按同一顺序(先 params、后 segments、同一拍)对齐。

## 兼容性影响

- **参数面**:参数集合 / 布局 / 值域 / 默认值未动,`params_v0.tsv` golden 不变,ABI 不变。
- **宿主自动化**:冻结维度上手动改仍会在宿主自动化车道留下一次带 gesture 的写入(#87 起的行为,未变)。
- **工程 state**:无新字段、无 schema 变更、**不需要迁移**(用户确认无存量用户)。既有测试工程里已经被
  烘焙出来的常值段仍可用 §1.6 的「重新识别(含手动段)」(`clearManual:true`)清掉 —— 那条链路一字未改,
  harness 用例 `HOST P0-3` 与 `HOST clearManual:true …` 继续全绿。
- **旧构建 / 旧 web**:桥函数签名与回执形状未变(`{ok, replacedSegments, replacedLocked}`),旧 web 不受影响;
  但旧 web 的读回值不按 freeze 位分叉,配新 native 时冻结维度会读到段表里的陈旧常值段(显示旧值、听感新值)。
  两侧同批发布即可,v1 未发布,无跨版本组合。
