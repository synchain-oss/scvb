## 变更内容

**一句话**:`min_segment_ms` 的上限 **500 → 2000**(下限 50、默认 120 都不动)。

| 面 | 改前 | 改后 |
| --- | --- | --- |
| 规格值域(02 §0.3) | `120 | 50..500` | `120 | 50..2000` |
| native 夹取(`OutputEditor` 的 `jlimit`) | `juce::jlimit(50, 500, …)` | `juce::jlimit(50, 2000, …)` |
| UI 滑杆行程 | `min: 50, max: 500` | `min: 50, max: 2000` |
| 页面侧夹取 `clampMinSegMs` | `Math.min(500, Math.max(50, n))` | `Math.min(2000, Math.max(50, n))` |
| mock 快照 / mock 校验 | 值域 50..500 | 同步到 50..2000 |
| VAD P1「丢短」 | `minHops = minSegmentMs / 10` ⇒ 上限 50 hops | 上限 **200 hops**(20 段/s × 2s);**本变更不新增上界**,但要确认段数/内存量级仍可接受 |
| 谷候选(`Segmentation.cpp`) | `minHops = llround(minSegmentMs / kHopMs)`、`minLen = msToSamples(...)` | 同上按新值域取值 |
| `restoreWindowTooShort` 口径 | 短段闸按夹取后的 `min_segment_ms` | **口径不变**(它读的就是夹取后的值);头注里的反例数字(420)要跟着新值域重算 |

**为什么要改**:MIN SEG 在真人声乐句上几乎无事可做(乐句 ≫500ms),上限抬到 2000ms 才让
「丢短段 / 并短段」在真素材上**可见**。用户 v5.6.13 回验 A20 报「变化很小、泳道图看不太出」,
SL-391 归甲(素材上短段本来就少)之后,这是让该参数真正可用的那一步。

## 兼容性影响

- **参数面**:ParamID / index / 顺序 / versionHint 全部不变,只是**允许的取值范围**变宽 ⇒
  既有工程的自动化数据、既有宿主会话全部照旧。
- **旧值 → 新版本**:老工程里存的 ≤500 的值**天然落在新值域内**,逐字不变。
- **新值 → 旧版本(降级)**:新版本写出的 1000ms 被老版本的 `jlimit(50, 500)` **静默夹到 500**。
  这是**已知降级方向**,与所有「值域放宽」类变更同形;v1 未发布,实际影响面为零,
  但要写进变更文档与 USER_GUIDE 的「版本兼容」句。
- **state**:字段类型仍是 `int`,编码不动,`abi` **不升**。
- **行为面(要写清)**:同样的素材在 50/120/500/1000/2000 五档下**段数应当单调不增**
  (丢短 / 并短更强)。这条是机检要钉的**方向**,不是「段数一定明显变少」——
  后者的前提是素材里真有 500–2000ms 的短段(见 house-rules §2 那次教训)。
