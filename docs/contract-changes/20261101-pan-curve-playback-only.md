## 变更内容

pan 角度域曲线 G 改成**只在播放时叠加**,和全局 Width 一样:

- 分析不再读 `versions[].pan_curve`。平衡的能量模型里不再有曲线增益,`BalanceConfig::panCurve` 字段删除,`startAnalysis` 不再把曲线传进分析配置。
- 改曲线不改分析结果,也不改写进宿主的 `v{v}_t{tt}_{pan|vol}` 车道。这些车道本来就只取自段表,打印器从不读 G。
- 播放侧不变:`renderSpan` 仍在 `P_eff` 上施加 G,实时与离线同路。
- 曲线不再是「建议重新平衡」的触发源。这个提示从未实现过,所以没有代码要改,只订正说法。

§1.37 原句写的是「存盘、`scvb.state` 回推、分析(左右平衡按 `pan_curve` 算)读的都是已提交的点表」,现在把「分析」从这份名单里拿掉,并写明分析不读 `pan_curve`。

**全局 Width 与每轨 width(同一裁定)**:两者都只在播放时起作用,不进分析,改了也不提示重新平衡。代码里分析本来就不读它们的实际值,这里只订正 `MixMath.h` 里把 width 当成触发源的注释。

### 为什么不算「改既有字段语义」

CLAUDE.md §7.4 禁止改既有字段的语义。`pan_curve` 这个字段的语义没有变:仍然是「这条曲线在播放时施加的增益」,字段形状、校验、回推都没变。变的是「谁读它」:分析这个读者走了。这一条由用户在批准时认定,仍按冻结契约流程走(批准、本文档、标签)。

## 兼容性影响

- **既有工程不重新分析:逐位不变。** 分析结果(含 u 与 δ)已经烘进存盘的段 pan/volDb,加载时直接使用,不重算;state 里也没有记录分析时用的是哪条曲线。所以不需要也无法迁移。
- **既有工程重新分析:画过非平坦曲线的,vol 会变,pan 有时也会变。** 曲线直接影响 u,也经回退链 level 2(`d0` 的符号)、level 3(δ 二分)与上一区间解间接影响 pan。这些入口都算重新分析:全量分析、范围分析、单轨恢复自动、拖 VAD/分段滑杆松手后的自动重分段。
- **范围分析**在整条时间线上算、只写回选区,所以选区边界可能出现音量台阶,直到做一次全量分析。
- **从没画过曲线的工程:逐位不变。** 空曲线下曲线增益恒为 1,删掉它不改变任何运算结果。
- **语义代价**:分析不再补偿曲线造成的左右差。比如只压右半边,混音就会偏左。这是这次变更要的结果,写进用户手册。
- 嵌套使用时,第一级的曲线已经算进交给第二级的组混音,所以「改曲线不影响分析」只在单个 Output 内成立。

记入 CHANGELOG「⚠️ 契约变更」(只在重新分析后可闻)。不进 KNOWN_ISSUES:这是行为变更,不是缺陷。不做加载提示,不自动重新分析。
