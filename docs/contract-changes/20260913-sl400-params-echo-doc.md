## 变更内容

**一句话**:把 [SL-400] 已经落地的形状写进 §2.2 的文字 —— `scvb.params` 的「值未变不发」判的是
**整个载荷**(含 `hostEcho`),所以**只翻回声位**的那一帧 `values` 是**空对象 `{}`**;
那是合法的稀疏 diff(= 「本帧没有 id 变化」),不是非法帧。

具体口径:

| 面 | 改前(文字) | 改后(文字) |
| --- | --- | --- |
| §2.2 字段纪律 · `values` | 「= **稀疏 diff**(只含本帧变化的 id)」 | 同一句 + 「`hostEcho` 翻转同样算载荷变了、该发;因此**只翻回声位的那一帧 `values` 可为 `{}`**,下游不得按异常帧过滤」 |
| §2.2 频率行 | 「**值未变不发**」 | 「**载荷未变不发**」——`values` 与 `hostEcho` 任一变化都算「载荷变了」,并指向下行的字段纪律 |
| §0.4(`:40`,推流总则) | 「**值未变不发**」 | 「**载荷未变不发**」(同一条口径:判的是整个载荷有没有内容,不是 `values` 必须非空) |
| §2.2 载荷行 / 其余各格 / 其它事件 | — | **不动**;§0.4 那一处只改这一个词,句子其余部分一字不动 |

**为什么是「只补文字」而不是「改契约」**:`hostEcho` 从 v1 起就是 `scvb.params` 载荷的一部分
(§2.2 载荷行),「载荷未变不发」说的又一直是**载荷**没内容就不发 —— 空 `values` 的帧本来就合法,
只是**文字没写**(§0.4 原来那句「值未变不发」还会把人读成「`values` 必须非空」)。本次补的是那句话
与那个词,不是新形状。

## 兼容性影响

- **载荷结构零变化** ⇒ `abi` 不升、段名不升 v2;mock 后端与 C++ 常量表无需改动
  (`check-bridge-parity.mjs` 比对的是名字集合,不含「空 `values` 是否合法」这一条形状)。
- **新旧版本互通**:老页面收到空 `values` 的帧时,`app.js` 的
  `{...store.params.values, ...(p && p.values)}` 展开空对象是 no-op;`hostEchoAt` 的写入只看
  `p.hostEcho`、不看 `values` 是否非空 ⇒ 播放期那把闩锁照样被这一帧武装。
  **谁把空 `values` 当异常帧过滤掉,「起播 chase」这条链就断在那里**
  (页面再也收不到 `hostEcho:true`,`宿主自动化正在写`那个徽标在播放中不亮 —— 正是 [SL-400] 要修的
  用户可见症状)。
- **行为面零变化**:本次只改文档,不改任何代码。
