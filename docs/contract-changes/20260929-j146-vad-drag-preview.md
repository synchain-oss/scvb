## 变更内容

### 为什么要新增一个事件(而不是复用)

§1.18 拖动档要「回发 VAD/边界预览」,但冻结契约里**没有任何承载预览的载荷**。逐个排除过:

| 候选 | 为什么不行 |
|---|---|
| 塞进 `setVadParams` 的返回值 | 预览会在调用**之外**结束(松手那一趟落地、撤销、切版本、空闲),返回值只能「来一次答一次」,收不了尾;UI 要自己镜像一套结束条件,两侧同错时没有任何门禁会红 |
| `scvb.segments` 加一个 `reason` | 那是**段表**的唯一数据源(§2.8「契约边界」),UI 收到就整轨替换段表、撤倒计时条、弹 diff;预览不是段表(没有 pan/vol/origin/locked),混进去会把真段表覆盖掉 |
| `scvb.state` 加一个运行时子树 | 25Hz 全量 diff 的载荷里塞每轨段列表,每拍都要重新序列化;且 §2.1 要求字段集与 §1.1 快照一致 |
| `requestWaveform` | 拉取式、一次调用一次回执、**绝不进事件流**(§0.3 第 3 条);它只能承载 VAD 着色(见下),承载不了「边界在哪」 |

所以**VAD 着色复用既有字段**(§1.27 的 `vad` 列),**边界预览走一个新事件**。

### §2.10 `scvb.vadPreview`(新增)

```
{ seq:u32, active:bool, startS?:f64, endS?:f64,
  channels:[ { ch:1..15, spans:[ {t0S:f64, t1S:f64} ] } ] }
```

- **何时发**:`setVadParams` / `setSegmentation` 每次调用当场重判决并发(调用方 web 已节流到 ≤50Hz;长会话单次太贵时自适应合并、
  由 25Hz 定时器补算后发,见下「代价与长会话」);预览结束时发一次
  `active:false`。按 `seq` 判变化;首帧只在正处于预览中时发(条件类)。
- **内容**:`active:true` 时 `startS/endS` = 松手那一趟的**写回窗**;`channels` = 写回集轨(启用、此刻已连接、窗内有采集数据 —— 与松手那一趟同一判据,含 [SL-535] 的「已连接」);
  每轨 `spans` = 该轨在**当前参数**下的 **S1 段**(VAD 状态机 + 超长段谷切分),裁到写回窗。
- **何时结束**:任何一趟分析落地;§1.18「丢弃」那三件事(撤销/重做真的动了栈、真切版本、宿主载入工程);
  空闲 1.5s(没有新拖动、没有已排的松手防抖、没有在跑的分析 —— 即抑制态松手或松手那一趟没受理)。

### §1.27 `requestWaveform.vad` —— 口径补写,不是改语义

05 §2.3 的「VAD 着色」行本就写着「后验≥判决的区间半透明绿罩 · **阈值拖动实时重着色** · 数据 `requestWaveform.vad[]`」;
契约 §1.27 只写了「VAD 判决位」,没说后验取自哪里,实现一直取「上一次分析写下的 vadP」,所以拖滑杆时绿带不动。
本次补写:**预览期间写回窗内取当前参数下即时重判决的后验,其余时候取上一次分析写下的后验**;判据不变
(该列任一 hop 后验 > 0.5)。松手那一趟落地后两者逐位相同(同一组参数、同一份特征、同一个窗)——
host 用例 `[j146]` 直接钉这一条。字段名、类型、列数、未覆盖列纪律一个字不动。**例外**(复审①后补):采集写入进行中(边播边采)时,预览里与参数无关的
那一半限频 1s 重建一次,期间沿用 ≤1s 前那份特征按当前参数照跑 —— 这时覆盖层与当下特征对不上,`vad` 列退回
上一次分析写下的后验(着色暂不随拖动变,虚影照常变)。不限频的话,长会话里每一次拖动调用都要在消息线程上
重新取样 + 两次整段排序,40Hz 连发会把界面与宿主存盘一起堵住。

### 预览的边界(写进 §1.18,免得被读成「预览 = 最终段表」)

预览只到**每轨 S1**:松手后的段表还会在**别的轨**的边界处再切开(02 §3.4 全局区间),同一区间 pan/vol 相同
的相邻块又会合回去 —— 所以最终段数可以多于预览段数。落在用户段(origin≠auto 或 locked)内部的预览边界,
UI 不画(松手那一趟逐字节不动用户段)。

### 代价与长会话(复审②后补)

`scvb_tests "[j146cost]"`(隐藏用例,本机,计算核):15 轨 × 4 分钟 —— 建缓存一次约 4.6 ms、命中缓存每次约
2.6 ms、不缓存每次约 5.7 ms;15 轨 × 60 分钟 —— 约 69 / 42 / 108 ms。目标 <50ms 在命中缓存时到 1 小时 × 15 轨
都成立,但那一档已贴着上限,而 web 侧 ≤50Hz 连发、不等回执 ⇒ 照单全收会把消息线程占满。所以 C++ 侧做
**自适应合并**:两次重判决的开始之间至少隔上一次耗时的两倍,期间的调用只记最新参数,由 25Hz 定时器补算
(占空比 ≤50%)。典型会话(一次约 3ms、调用间隔 25ms)恒为当场算,与不合并时行为相同。

## 兼容性影响

- **既有工程**:零影响。不改 state、不改参数、不改 IPC。预览不写 vadP,存盘字节与改动前逐位相同。
- **既有 DAW 自动化**:零影响。预览不碰参数面、不发 gesture、不碰音频线程。
- **撤销栈**:零影响。预览不入栈;松手那一趟仍是一条撤销步([J95③a],不变)。
- **与 [SL-445] 快照池回收(#306)**:**零交集**。预览不发布任何播放快照、不碰 `OutputAuthority` / `DspArbiter`;
  松手那一趟与改动前一样只发布一次。拖动中占用的内存只随「已采集时间线 × 写回集轨数」变化,与拖动时长无关,
  预览结束即整份释放(host 用例钉「连拖 N 次缓存只建一次、结束后占用归零」)。
- **新旧 UI 互通**:不适用 —— web UI 经 `juce_add_binary_data` 编进插件二进制,与 native 同包发布,不存在新旧混搭。
