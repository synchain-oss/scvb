## 变更内容

**一句话**:`lead_select` 选中的轨,由「只在播放时被强制拉到正中」改为**在分析里就被当作主唱**:该轨在它被选中的那些区间
并入集合 C(与 `lead_lock` 同一条路径 —— 恒居中、不占槽),其余声部按剩下的轨数排槽,音量平衡也把它当作居中的那一轨来算。
写进段表 / 打印进宿主自动化的曲线因此本身就体现了「主唱在中间、其余围绕它」。

**为什么要一份时间线记录**:`lead_select` 是宿主可自动化的参数(J58「每句换主唱」),插件拿不到宿主的自动化曲线,
只能在**播放经过时**看到它当下的值。所以:

1. Output 在走带播放(时间线有效、t0 ≥ 0)时,每个音频块把 `lead_select` 的值连同这一块的样本区间 push 进一个
   无锁单生产者单消费者队列(音频线程不分配、不加锁);
2. 消息线程每拍(以及点分析、存盘前)把队列排干进 `LeadTimeline`:样本域的分段常值记录,**后放覆盖先放**、相邻同值合并;
3. 点分析时,计算窗内的记录随作业配置进管线;管线逐个全局区间取**多数值**(按已记录样本数,平局取小值);
   结果 n ∈ 1..15 且轨 n 在该区间活跃 ⇒ 该轨在这个区间按主唱锁处理。[J143a] **只在记录算得上自动化**(计算窗里
   有 ≥ 2 个不同的值)时才这么取,整段无记录的区间取点分析那一刻的 `lead_select`;记录 ≤ 1 个值时整窗都取后者。
4. 记录随工程落盘(`LEAD` 块),重开工程再分析,主唱仍在分析里。

**播放期覆盖层保留**(`DspArbiter` 的「选中轨 pan 目标 := 0」一句不动):按同一份记录分析过的区间里,主唱那一轨在它自己的段上
曲线本来就是 0,这一句不改变听到的东西;它仍兜住分析够不着的几种状态 —— 改了 `lead_select` 之后还没重新分析的区间、
冻结 pan 的轨(那一维读参数面,不读曲线)、跟随宿主档(不读曲线)、没有记录的旧工程。这些状态下「选中即居中」照旧成立,
但其余声部要等重新分析才会重新排布。

**`LEAD` 载荷**(小端):`u16 minor`(=1)| `u16` 保留(写 0)| `u32 条数`(≤ 65536)|
条数 × `{ i64 t0 | i64 t1 | u32 lead }`(每条 20 字节;t0 ≥ 0、t0 < t1、按 t0 升序互不重叠、lead ∈ 0..15)。

| 读到的形态 | 处置 |
| --- | --- |
| 完整工程(带 `CFGS`)、有合法 `LEAD` | 记录整份换成它 |
| 完整工程、无 `LEAD`(旧工程 / 从没播过) | 记录清空 ⇒ [J143a] 重新分析时整窗按点分析那一刻的 `lead_select`;它为 0 时与改动前逐位相同 |
| 完整工程、`LEAD` 长度 / 顺序 / 值域不合法 | 整块不用、记录清空(派生数据,重放一遍即可补回;不为它整份拒载工程) |
| 完整工程、`LEAD` 的 minor 高于本构建 | 按「没有记录」起步;保存时**原样回写**那份字节(自留一份,不依赖 `loadedChunks_`)。⚠ 这一状态下本构建新播的记录照样进分析,但**只在本次会话内有效** —— 存盘写回的是旧字节,重开后这些记录不在了 |
| 只带 `PRMS` 的轨道 / 参数预设 | 不动内存里的记录(与 FEAT / 通道配置同一个落点) |

## 设计取舍(交统筹核)

- **两条主唱**:`lead_select` 只能选一条;它与 `lead_lock` 的轨取并集进 C。C 本来就允许多轨共占中心(02 §5.2),
  不新增规则。⚠ Tracks 页「多主唱居中」琥珀提示只数 `lead_lock` 的轨(`web/output/tab-tracks.js`),
  `lead_select` 再选一条不同的轨时不会亮 —— 本卡不改 UI,记为待议项。
- **主唱是配对(pair)成员**:沿用 02 §5 既有优先级「lead_lock 优先,pair 忽略」—— 另一名成员按普通自由轨排。
- **主唱冻结了 pan / 不参与自动声像**:沿用既有分类优先级 leadLock > 冻结 pan > 不参与,分析里它都是 0;
  冻结轨播放时读参数面,由保留的覆盖层保证居中。
- **一个区间里主唱中途换人**:取多数值,不在换人处另切区间。全局区间由各轨段边界切出,通常比一句话短,换人又多落在句间,
  实际偏差是「晚一个区间换」。要按换人点精确切区间,得改 §3.4 的区间构造,不在本卡。
- **改了 `lead_select` 不自动重分析**:要点重新分析,与中心槽策略 / 响度口径「改后需重分析」同一类。[J143a] 没有自动化时
  不必先播一遍(整窗按点分析那一刻的值);改了自动化才要把改过的那段播一遍,让 Output 记下新值。
  自动重分析会在「每句换主唱」的自动化下每句触发一次,且每次都是一条撤销步,不可取。

## 兼容性影响

- **既有工程**:没有 `LEAD` 块 ⇒ 没有记录;播放期覆盖层照旧、段表不动 ⇒ **重开即听到的与改动前相同**(不重新分析就什么都不变)。
  [J143a] 重新分析时整窗按点分析那一刻的 `lead_select`:为 0 ⇒ 与改动前逐位相同;选了轨 n ⇒ 得到「主唱进分析」的新排布,不必先播一遍。
- **既有 DAW 自动化**:不受影响(参数面零变更;`lead_select` 仍不打印、host 恒权威)。
- **新旧版本互通**:新版写 → 旧版读,`LEAD` 按「未知 fourcc 原样保留回写」保真(旧版分析不读它);旧版写 → 新版读,无此块即「没有记录」。
- **撤销 / 版本 / 冻结语义**:不变。记录是分析的输入(与 FEAT 同类),不进撤销栈、不分版本;分析本身的撤销照旧。

## 追加:J143 / J143a —— 点分析那一刻的 Lead Select(SL-545)

**缺口**:上面那套只认播放时的记录。而**采集本身就是走带播放** —— 采集过的地方全有记录,值是采集那会儿的
`lead_select`(通常 0)。于是「采完改了 Lead Select、不重播直接点分析」仍按记录里的 0 分析,选中的轨不居中;
旧工程(有特征、没有 `LEAD`)同理。

**J143**(统筹,2026-09-28):没有记录的区间用点分析那一刻的 `lead_select`,有记录的区间仍按记录。
**J143a**(统筹,同日,取代 J143 的字面版):先数**计算窗**里的记录一共有几个不同的值(`distinctLeadValues`;
没记录的空档不算,0 也算一个值):

| 计算窗里的记录 | 每个区间的主唱 |
| --- | --- |
| 没有记录 / 只有一个值(全 0,或全是同一轨) | **整窗**取点分析那一刻的 `lead_select`(记录不看) |
| ≥ 2 个不同的值 | 按记录取多数值(同上文第 3 条);一个已记录样本都没有的区间才取点分析那一刻的值 |

理由:一份恒定的记录不比旋钮当前值多带任何信息,用户最后一次的设定就是意图 —— 这也顺带修好了
「播的时候是 3、播完改成 5、不重播就分析」(按 5)。刻意自动化成 0 的句子(合唱 / 无主唱)保得住:
自动化里某处有 0,别处必有非 0,窗里就是 ≥ 2 个值,0 那几句照记录走。

**落点**:`analysis::majorityLead` 多一个回落参数(整段无已记录样本时返回它,缺省 0);`analysis::distinctLeadValues`
新增;`PipelineConfig::leadFallback` 新增;管线在区间循环前按计算窗算一次「是不是自动化」,区间里据此取值;
Output 在 `startAnalysis` 装配处把 `lead_select` 的当前值(与播放记录同一个取整夹值口径)填进 `leadFallback`。
实时路径(`processBlock` 的记录、`DspArbiter` 的覆盖层)**一行未动**。

**已知边角**(照实写,不是判据漏洞):**计算窗是整条已采集时间线**(范围分析也一样,见 `startAnalysis`
「计算窗 = 整条已采集时间线」;选它是为了让范围分析与全量分析在窗内同解),所以「只有一个值」判的是**全部已记录
的部分**,不只是这次选中的范围。于是:已播过的部分自始至终只有一个 `lead_select` 值(典型:采集完才写的自动化、
之后没再播过),而播放头停的位置上自动化读出另一个值 ⇒ 整条时间线都按停带位置的值分析。补救:把播放头停到自动化
就是想要的那个值的地方,或把自动化会变值的一段播一遍(让记录里出现 ≥ 2 个值),再重新分析。**只重播一段不变值的
范围补救不了** —— 那只会再记一遍同一个值。USER_GUIDE 双语已写明。

**兼容性**:参数面、`LEAD` 载荷、容器 abi、桥面均零变化。已分析过的工程在重新分析之前段表不动(分析只在点分析时跑);
重新分析时按上表取值。冻结契约里受影响的两句一并订正:`docs/PARAMETERS.md` 的 `lead_select` 说明列、
`docs/STATE_SCHEMA.md` §三 `LEAD` 兼容说明里的「无此块 ⇒ 分析与改动前逐位相同」(现为「当前值为 0 时」)。
