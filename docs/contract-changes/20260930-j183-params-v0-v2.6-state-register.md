### 几条取舍

- **`abi` 写数还是写指路**:写数(6)并注明「登记时的值,往后以 `STATE_SCHEMA.md` §三 为准」。只写指路的话,冻结点上三份文档读不出
  一个可核对的数;只写数、不写指路的话,下一次升 abi 又会像这次一样只改 `STATE_SCHEMA` —— 这次的 1 / 2 就是这么留下来的。
  `STATE_SCHEMA.md` 是编码真源,每次升 abi 都必须改它,所以「当前值」只放在那里。
- **bypass 一句**:JUCE 8.0.8(仓内 `.juce-version`)的 VST3 wrapper 在插件没有自己的 bypass 参数时自建一个
  `AudioParameterBool`(ID `byps`),参数信息带 `kCanAutomate | kIsBypass`(`modules/juce_audio_plugin_client/juce_audio_plugin_client_VST3.cpp`
  `Param` 构造处)。宿主能自动化它,「不占自动化位」因此不对 —— Output 的「宿主可见 124」本来就把它算在内;它不占的是插件自己声明的参数
  (Output 的 123 个)的预算。宪法 §一 与 `PARAMETERS.md` 各有一处,本次都改。
- **Monitor state 为什么现在才登记**:立项时的 `20260825-monitor-target.md` 写「STATE_SCHEMA 零新增」—— 布局确实没新增(复用 Input 的
  `InputStateCodec`),但「Monitor 有 state、用的是这个布局、兼容处理和另两个插件不一样」一直没有写进任何冻结文档。本次补的是登记,
  `20260825-monitor-target.md` 是历史变更文档,不改。
- **`excluded_ranges[]` 怎么写才不误导**:它在 CRVS 布局里、编解码原样往返,但 v1 没有任何编辑操作产生它、分析也不读它。
  只写设计语义(「重分析时防复活」)会让人以为它在起作用,所以三份文档都同时写了「v1 不产生、不读」。
- **SCVB_CONTRACT 的字段集指路**:§1.1 / §2.1 的「真源」格写着「字段集 params-v0 §二」,那是溯源标记;桥面快照实际下发哪些键,
  以 §1.1 返回格里逐项列出的对象为准,本次一个键都没加。`global.range` 从宪法 §二 撤回之后照旧在桥面(运行期镜像,
  `STATE_SCHEMA.md` §三 [J102] 那条早就这么写)。新补登的 `lead_timeline[]` / `meta` / `excluded_ranges[]` 等不下发到桥面,
  本来就不在 §1.1 的列表里。
